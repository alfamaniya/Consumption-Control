### تکمیل چهار مرحله ماژولارسازی بکاپ

1. **انتقال انتخاب پوشه و مجوزها:** انجام شد؛ در `settings/backup-folder.js` با دسترسی به IndexedDB و File System Access API.
2. **تکمیل API مشترک:** انجام شد؛ تنظیمات از `window.AnbarCore.settings` به عملیات بکاپ و مدیریت پوشه متصل است و وابستگی‌ها هنگام ساخت ماژول تزریق می‌شوند.
3. **انتقال بازیابی JSON:** انجام شد؛ خواندن چند فایل، انتخاب snapshot، تحلیل مغایرت، پیش‌نمایش و اجرای بازیابی در `settings/backup-restore.js` قرار دارد.
4. **اتصال هفت سکشن و مستندات:** اتصال ساختاری هر هفت سکشن به Loader برقرار و درخت/جدول این README به‌روزرسانی شد.

قرارداد JSON، schemaVersion، کلیدهای localStorage، تاریخچه افزایشی، نام‌گذاری خورشیدی و مسیر بازیابی با rollback حفظ شده‌اند. آزمون مرورگر واقعی و ساخت خروجی مستقل عمداً در این نوبت اجرا نشده‌اند.

## معرفی

Anbar یک برنامه وب فارسی و راست‌به‌چپ برای ثبت ورود کالا، نگهداری موجودی، ثبت ارسال، گزارش‌گیری، کاردکس، مدیریت و پشتیبان‌گیری است. نسخه چندفایلی برای اجرا از طریق وب‌سرور محلی یا HTTPS طراحی شده است. نسخه `anbar-standalone.html` خروجی اختیاری و تولیدی است؛ هر دو Workflow ساختار کد و انتشار GitHub Pages هنگام اجرا آن را از منابع فعلی بازتولید می‌کنند. در صورت نیاز به به‌روزرسانی محلی نیز می‌توان اسکریپت ساخت را دستی اجرا کرد.

## اکسپلورر خودکار تگ‌ها و قابلیت‌ها

سکشن «اکسپلورر تگ‌ها» ساختار واقعی DOM را از روی سکشن‌های بارگذاری‌شده استخراج می‌کند؛ فهرست سکشن‌ها، کارت‌ها، فرم‌ها، جدول‌ها و کنترل‌ها به‌صورت دستی در کد اکسپلورر نگهداری نمی‌شود. درخت با افزودن یا حذف عناصر DOM و تغییر شناسه/کلاس/ویژگی‌های ساختاری، از طریق `MutationObserver` دوباره اسکن می‌شود. جست‌وجو و پنل جزئیات نیز از همان ساختار زنده تغذیه می‌شوند.

```text
tag-explorer/
├── tag-explorer.html   # پوسته رابط اکسپلورر
├── tag-explorer.css    # استایل مستقل و واکنش‌گرا
└── tag-explorer.js     # کشف DOM، ساخت درخت، جست‌وجو و جزئیات
```

این ابزار تگ HTML، شناسه، کلاس‌ها، نقش ARIA، نوع ورودی، مقصد پیوند، ویژگی‌های داده‌ای و نوع تعامل قابل استنباط از عنصر را نمایش می‌دهد. مرورگر امکان فهرست‌کردن عمومی listenerهای رویداد ثبت‌شده با `addEventListener` را نمی‌دهد؛ بنابراین ابزار ادعا نمی‌کند منطق داخلی همه handlerها را کشف می‌کند. فایل‌های این پوشه توسط Loader بارگذاری و در Build نسخه مستقل جاسازی می‌شوند. برای افزودن قابلیت جدید، نیازی به ویرایش اکسپلورر نیست؛ کافی است قابلیت در DOM واقعی صفحه حضور داشته باشد.

## قراردادهای اتصال فایل‌ها

1. HTML هر هفت سکشن از فایل مستقل پوشه خودش با نگاشت `sections-loader.js` بارگذاری می‌شود؛ `index.html` فقط پوسته و mountها را نگه می‌دارد.
2. هر فایل سکشن در پوشه ریشه متناظر خودش باید یک عنصر ریشه `section.section-card` با ID متناظر mount داشته باشد.
3. ابتدا `settings/backup-validation.js` و `settings/backup-engine.js` بارگذاری می‌شوند؛ سپس `index.js` اجرا می‌شود و `window.AnbarCore` را منتشر می‌کند؛ سپس ماژول‌های موجودی، داشبورد، ورود، مدیریت، کاردکس و گزارش‌ها بارگذاری می‌شوند. ماژول گزارش‌ها از API هسته برای خواندن سوابق ارسال، قالب‌بندی اعداد/تاریخ، ساخت جدول و راه‌اندازی تقویم خورشیدی استفاده می‌کند.
4. تغییر ID، نام کلاس یا ساختار فرم‌ها باید هم‌زمان در HTML، CSS و JavaScript بررسی شود.
5. `anbar-standalone.html` خروجی است؛ HTML سکشن‌ها، CSS عمومی و اختصاصی و payloadهای هسته و ماژول‌ها در آن جاسازی می‌شوند.
6. تغییر کلیدهای ذخیره‌سازی یا ساختار رکوردها بدون طرح مهاجرت سازگار ممنوع است.

### رفتار گردش انتشار

- با هر Push به شاخه `main` اجرا می‌شود.
- اجرای دستی از بخش Actions نیز با `workflow_dispatch` امکان‌پذیر است.
- ابتدا Node.js و ابزارهای اعتبارسنجی آماده می‌شوند.
- ساخت نسخه مستقل، کنترل نحوی JavaScript/CSS و اعتبارسنجی HTML اجرا می‌شوند.
- فقط در صورت موفقیت مرحله ساخت، فایل‌های سایت به‌عنوان Pages artifact بارگذاری می‌شوند.
- در مرحله بعد با `actions/deploy-pages@v4` سایت منتشر می‌شود.
- مجوزهای لازم به‌صورت محدود تعریف شده‌اند: `contents: read` برای ساخت و `pages: write` و `id-token: write` برای انتشار.
- اجرای هم‌زمان انتشارها در گروه `github-pages` کنترل می‌شود تا انتشار قدیمی‌تر با اجرای جدیدتر تداخل نکند.
